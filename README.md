# Savebot

Свой бот вместо кучи чужих: кидаешь ссылку — получаешь файл. Без рекламы, без обязательных подписок на каналы, отвечает только тем, кого впишешь.

**Что умеет**

| Ссылка | Что придёт |
| --- | --- |
| YouTube, Shorts | кнопки качества с примерным весом (1080p · 62 МБ…), MP3, M4A |
| TikTok, Instagram, X, VK, SoundCloud и ещё сотни сайтов | то же самое — всё, что умеет [yt-dlp](https://github.com/yt-dlp/yt-dlp) |
| Spotify: трек | сразу mp3 с названием, исполнителями и обложкой из Spotify |
| Spotify: альбом или плейлист | список треков и кнопка «Скачать все» |
| Плейлист YouTube | кнопка «MP3 всех» |

Уже скачанное второй раз приходит мгновенно: Telegram хранит файл у себя, бот помнит его `file_id`.

**Как Spotify.** Звук в Spotify под защитой, поэтому бот, как и все такие боты, берёт у Spotify только описание трека, находит тот же трек на YouTube Music (сверяя длительность и отсеивая live, каверы, ремиксы) и качает звук оттуда. Ключи Spotify не нужны.

## Где что лежит

| Файл | Что это |
| --- | --- |
| `bot.py` | бот: ссылки, кнопки, очередь, отправка, кэш file_id |
| `dl.py` | yt-dlp: сведения о ролике, кнопки качества, скачивание, превью |
| `spotify.py` | описание со страницы плеера Spotify, поиск на YouTube Music, теги mp3 |
| `tests/` | проверки без интернета: `python -m pytest tests` |

## Запуск на Railway

1. **Новый бот.** В @BotFather — `/newbot`, токен в `TELEGRAM_TOKEN`. Mindgate не трогаем: у него свои дела с текстом и голосом.
2. **Сервис.** Railway → New → GitHub Repo → этот репозиторий. Dockerfile подхватится сам (в нём ffmpeg и deno, без них YouTube не качается).
3. **Том.** Сервис → Settings → Volumes → путь `/data`. Там кэш file_id и куки. Без тома всё работает, но кэш стирается при каждом обновлении.
4. **Переменные** (см. `env.example`): `TELEGRAM_TOKEN`. `ALLOWED_IDS` сначала оставь пустым, напиши боту — он ответит твоим id. Впиши его (и через запятую id девушки, если надо).

Публичный домен не нужен: бот сам спрашивает Telegram, вебхуков нет.

yt-dlp обновляется при каждом запуске (`start.sh`): YouTube ломает его раз в несколько недель, и чаще всего «перестало качать» лечится кнопкой Restart в Railway.

## Если YouTube не пускает

С серверов YouTube часто отвечает «Sign in to confirm you're not a bot». Бот обходит это сам, по очереди:

1. другие клиенты YouTube — телевизор, мобильный сайт, VR-приложение;
2. **свой прокси** из `PROXY_URL`, если задан;
3. **Tor**: бот поднимает его сам, и каждая попытка идёт через новую выходную точку — какую-то YouTube да пропустит (выключить — `TOR=off`);
4. для треков из Spotify — **SoundCloud**, если YouTube не пустил совсем. Бот сверяет название и длину и отсеивает 30-секундные превью и ремиксы.

Cloudflare WARP тоже есть, но выключен: он ходит по UDP, а Railway исходящий UDP не пропускает. На другом хостинге — `WARP=on`.

Сработавший путь бот запоминает и дальше начинает с него. В логах Railway видно, какой: «YouTube пустил: …».

**Свой прокси.** Самый надёжный способ без компьютера. Нужен «резидентный» или «мобильный» прокси: у дата-центровых те же проблемы, что у Railway. Аудио весит мало, так что тарифа за трафик хватит надолго. Строку подключения от сервиса — в `PROXY_URL`, например `http://логин:пароль@хост:порт`.

**Куки — если обходы не помогли.** Нужен запасной Google-аккаунт — не основной: YouTube может заблокировать аккаунт, с которого качают.

С iPad — через браузер Orion (от Kagi, App Store), он умеет ставить расширения Chrome:
1. В Orion включи поддержку расширений и поставь из Chrome Web Store «Get cookies.txt LOCALLY».
2. Зайди на youtube.com запасным аккаунтом.
3. Расширением выгрузи `cookies.txt` для youtube.com и через «Поделиться» отправь файл боту в Telegram. Бот проверит, что в файле есть вход в аккаунт, начнёт с ними работать и удалит сообщение из чата.
4. Больше не открывай YouTube в Orion под этим аккаунтом: YouTube меняет куки при каждом визите, и выгруженные перестанут работать.

С компьютера — то же расширение, но в приватном окне, которое сразу после выгрузки закрыть.

Можно и без файла: вставить текст cookies.txt сообщением боту или в переменную `YT_COOKIES`. Переменная при перезапуске перекрывает присланный файл.

## Большие файлы (до 2 ГБ)

Облачный Telegram принимает от ботов файлы до 50 МБ. Аудио бот пережимает, чтобы влезло, а видео упирается в лимит: это примерно 2–3 минуты в 1080p. Кнопки, которые не влезут, бот помечает ⛔.

Свой сервер Bot API поднимает лимит до 2 ГБ: двухчасовой ролик в 720p или почти час в 1080p.

1. **Ключи.** [my.telegram.org](https://my.telegram.org) → войти по номеру → API development tools → заполнить форму (название любое, платформа Other) → скопировать `api_id` и `api_hash`.
2. **Сервис.** В проекте Railway: **+ Create** → **Docker Image** → `aiogram/telegram-bot-api`. Переименуй его в `bot-api` (Settings → имя), иначе адрес ниже будет другим.
3. **Переменные сервиса bot-api:**
   ```
   TELEGRAM_API_ID=...
   TELEGRAM_API_HASH=...
   TELEGRAM_HTTP_IP_ADDRESS=[::]
   ```
   Последняя строка нужна, чтобы SaveBot достучался до него по внутренней сети Railway. Домен ему не нужен.
4. **В SaveBot** добавь `LOCAL_BOT_API_URL=http://bot-api.railway.internal:8081`.

При первом запуске SaveBot сам отвяжет бота от облачного Telegram — открывать ссылки с токеном не нужно. Кнопки сразу покажут новый лимит.

Вернуться на облако: удали `LOCAL_BOT_API_URL` и подожди минут 10 — облако примет бота обратно.

Трафик: Railway берёт плату за исходящий трафик, отправка каждого гигабайта в Telegram стоит несколько центов.
